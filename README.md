# Credit Risk Portfolio Monitor

Interactive credit-risk dashboard (Streamlit) built from 5 synthetic bank tables, with two embedded AI features:
**Ask the Portfolio** (LLM Q&A grounded in the data) and **Anomaly detection** (peer + own-history review queue).

**Python:** 3.13 (tested on 3.13; packages pinned in `requirements.txt`).

## Run it (three commands)
```bash
pip install -r requirements.txt            # 1. install
python -m src.build                        # 2. build the clean dataset, models, anomaly flags (~1 min)
streamlit run app/app.py                   # 3. start the dashboard
```
(The app also runs step 2 by itself on first start if `data/processed/` is missing. Tests: `python -m pytest tests -q`. Rebuild the two PDFs: `python -m src.make_docs`.)

## LLM API key
* Local: the key is read from the environment, so export it before step 3: `export ANTHROPIC_API_KEY=...` (`.env.example` lists the variable names; `.env` is not auto-loaded).
* Streamlit Community Cloud: App settings > Secrets > `ANTHROPIC_API_KEY = "..."`.
* Optional `LLM_MODEL` env var (default `claude-sonnet-5-5`).
* **No key set:** the app still works. Ask the Portfolio switches to a small built-in set of question patterns (default rate / exposure by a dimension, highest/lowest, overall rate, flagged counts, model AUC/Gini/KS). It uses the same read-only SQL path and shows the SQL and rows, and it declines anything else. The anomaly feature needs no key. If the LLM call fails (bad key, network), it falls back the same way and says so.

| 3. Default model: logistic baseline + LightGBM, AUC/KS/Gini, SHAP, monitoring | `src/model.py`; results in `data/processed/model_metrics.json`; dashboard **Model & monitoring** tab |

## Key design choices
* Grain = loan account (14,685); every join is a LEFT join from `loan_accounts` and the row count is asserted.
* No leakage: collections data (a consequence of delinquency) is not a model input; gender and marital status are excluded; splits are grouped by customer; dashboard scores are out-of-fold.
* Model: signal in this synthetic data is moderate (hold-out AUC about 0.67). A shallow, strongly regularised LightGBM is only on par with logistic regression, and both are reported.
* Ask the Portfolio: the LLM can only learn facts through a SELECT-only SQL tool on an in-memory copy of the data; the answer's numbers are re-checked against the returned rows (a heuristic: it catches invented figures, not a wrongly specified query, which is why the SQL is always shown).
* Analyst decisions are written to a local CSV; hosted free tiers have ephemeral disks, so production would use a database.
